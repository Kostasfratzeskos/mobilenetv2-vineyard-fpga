An int8 MobileNetV2 classifies grape leaves (Black Rot, ESCA, Healthy, Leaf Blight) on a
hand-written Verilog-2001 accelerator in the programmable logic of a Zynq UltraScale+ ZCU104
(XCZU7EV). This repository is the evidence for an NTUA diploma thesis: the software model, the RTL
and its testbenches, the PS firmware, the Linux camera application, and the LaTeX manuscript in
`thesis/`.

## Start here
- The current status is the "Status" paragraph of `README.md` plus the last entries of
  `docs/lab_notebook.md`. Read both before planning work. Status isn't repeated here because it
  changes every week.
- The reasons behind the design are in `docs/design_decisions.md` (DD-001 onward). Cite the DD id
  when you explain or defend a choice.
- `docs/claude_project/` is a gitignored summary written for a claude.ai Project, dated in its
  `00_START_HERE.md`. It is derived from the records and may lag them, so it is never a source.

## Ground rules
- The int8 software model is the source of truth. Every hardware block is bit-exact against the
  golden vectors (DD-006). A mismatch is a failure even when it is one LSB.
- One model on every platform (DD-036). Generated files and reports name their checkpoint's sha.
  Before touching accuracy, the export, golden sets, board results or thesis numbers, check that
  every artifact involved names the same checkpoint.
- Widths and limits come from provable bounds, not from measurements (DD-019).
- Label every number as measured, derived or estimated, and name its source. If the repository
  doesn't record something, say so instead of filling the gap.
- Never copy a number that a script produces: run the script again. Architecture figures come from
  `python scripts/analyze_workload.py`, thesis figures from `make -C thesis numbers`.
- Scope (dataset, model, platforms, success tiers) is agreed with the supervisor. Propose changes
  to it; don't make them.

## Commands
Run these in the Bash tool (Git Bash), from the repository root. Not PowerShell: there, `bash`
starts WSL's bash instead of Git Bash, and `make` doesn't exist.

| Task | Command |
|:--|:--|
| One testbench | the `// Run:` line in its header, e.g. `bash scripts/run_sim.sh requantize` |
| Testbenches by name, or all 35 | `bash scripts/run_all_sims.sh [name ...]`. A full run is slow, so run it in the background |
| C reference model | `make -C software/cmodel test` |
| Firmware host tests and lint | `make -C firmware test` and `make -C firmware/linux test` |
| Thesis PDF | `make -C thesis` (also `make -C thesis todo` and `make -C thesis check`) |

Skills cover the multi-step workflows: `/run-testbenches`, `/build-thesis`,
`/write-thesis-section`, `/log-session`, and `/redeploy-model` (manual only). Before thesis text
is committed, offer a review by the `thesis-fact-checker` agent.

## Records
- A session that produces a result (a measurement, a verification run, a board run) or a decision
  ends with a dated entry in `docs/lab_notebook.md`. A choice the author could be asked to defend
  gets the next DD entry. `/log-session` has the format.
- When a result changes, update every place that states it in the same change: the README status,
  the sub-READMEs and `thesis/manual_numbers.tex`.
- The thesis marks unfinished work (`TODO(BOARD)`, `TODO(COMPARISON)`). Never write it up as done.

## Git
- Commit only when asked. Pushing always asks first (`.claude/settings.json`). Never rewrite
  history that has been pushed.
- Commit subject: `area: what changed`, e.g. `thesis: ...`, `docs, READMEs: ...`, `redeploy: ...`.
  The body says what was measured or decided and why, with the numbers.
- Line endings: git stores LF, and `core.autocrlf=true` checks text out as CRLF. Don't convert
  files by hand. A Python script that rewrites a text file opens it with `newline=''`. Files that a
  Linux host reads need `eol=lf` in `.gitattributes` (`firmware/linux/petalinux/**` already has it).
- Untracked on purpose, and slow or impossible to rebuild: `data/` (the datasets) and every golden
  set except `healthy_9111` and `image_1`. Don't delete them without asking.

## This machine (Windows 11)
- Vivado and Vitis 2022.2 are under `C:/Xilinx`, and `run_sim.sh` finds xsim by itself. Python 3.13
  is `C:\Python313\python.exe`.
- The repository path contains Greek letters (`ΣΧΟΛΗ`), so quote every path. Keep scratch paths
  short: Windows' 260-character limit once broke a golden-set export.
- In the Bash tool, multi-line inline scripts (heredocs, `python -c "..."`) can lose their
  backslashes or hang. Write the script to a file and run the file.
- xsim sometimes fails for reasons unrelated to the design: antivirus file locks, or "child exe not
  found". Read the log, then re-run only those testbenches before you believe the failure.
- PetaLinux builds run in WSL2 (`Ubuntu-20.04`). See `firmware/linux/README.md`.
